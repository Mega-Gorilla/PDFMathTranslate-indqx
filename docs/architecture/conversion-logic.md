## 処理フロー概要

### 1. 核心概念：段落境界の計算

**重要**: 本システムはPDFの構造的な「テキストボックス」を認識するのではなく、
**文字の座標から動的に段落境界を計算**します。

```
┌─────────────────────────────────────────────────────────────────────────┐
│  元PDF上の文字配置から境界を計算                                        │
│                                                                          │
│      x0=50                              x1=300                           │
│      ├──────────────────────────────────┤                               │
│      H e l l o   W o r l d               │ y=700 (最上部の文字)          │
│      T h i s   i s   a                   │                               │
│      t e s t   t e x t .                 │ y=670 (最下部の文字)          │
│                                                                          │
│  各文字の座標から境界を動的計算:                                        │
│    x0 = min(全文字のx0) = 50                                            │
│    x1 = max(全文字のx1) = 300                                           │
│    y0 = min(全文字のy0) = 670                                           │
│    y1 = max(全文字のy1) = 700                                           │
│                                                                          │
│  → Paragraph(x0=50, x1=300, y0=670, y1=700, height=30)                  │
└─────────────────────────────────────────────────────────────────────────┘
```

**コード** (converter.py 行425-429):
```python
# 段落境界を更新（文字を処理するたびに更新）
pstk[-1].x0 = min(pstk[-1].x0, child.x0)  # 左端
pstk[-1].x1 = max(pstk[-1].x1, child.x1)  # 右端
pstk[-1].y0 = min(pstk[-1].y0, child.y0)  # 上端
pstk[-1].y1 = max(pstk[-1].y1, child.y1)  # 下端
```

```
│ ※ フォントはNoto(非ラテン文字用)に変更される                            │
```

### 3. 重要な補足事項

| 項目 | 説明 |
|------|------|
| 元テキスト | 出力PDFからは**削除**される（翻訳テキストで完全に置換） |
| フォント | 非ラテン文字はNotoフォントに**変更**される |
| 座標 | 段落の開始位置(x, y)から描画を開始し、境界(x0, x1)内で折り返す |
| 最小縮小率 | 50%が下限（可読性を維持） |
| 数式 | 元の座標・フォントで描画（翻訳されない） |

## Phase A: 元PDFの解析

**ファイル**: `converter.py` 行333-459
**目的**: PDFから文字・座標・フォント情報を抽出し、段落単位にグループ化

### A.1 文字の読み取り

pdfminerが各ページの文字を`LTChar`オブジェクトとして提供します。

```python
for child in ltpage:
    if isinstance(child, LTChar):
        # 文字処理
```

**LTCharの主要属性**:
| 属性 | 説明 |
|------|------|
| `x0`, `y0` | 文字の左下座標 |
| `x1`, `y1` | 文字の右上座標 |
| `size` | フォントサイズ |
| `fontname` | フォント名 |
| `get_text()` | Unicode文字 |
| `matrix` | 変換行列（縦書き判定に使用） |

### A.2 レイアウト領域の判定

DocLayout-YOLOモデルがページ画像を分析し、各座標がどの領域に属するかをマップ化:

```python
layout = self.layout[ltpage.pageid]  # numpy配列
cx, cy = int(child.x0), int(child.y0)
cls = layout[cy, cx]  # 領域クラス
```

**領域クラス**:
| 値 | 意味 |
|----|------|
| 0 | 除外領域（数式・図表） |
| 1 | 予約 |
| 2+ | テキスト領域（同じ値 = 同じ段落） |

### A.3 段落の構築

文字を段落単位にグループ化する際の判定ロジック:

```
同じ段落の条件: cls == xt_cls (直前文字と同じ領域クラス)

┌─────────────────────────────────────────────────────────────┐
│  child.x0 > xt.x1 + 1    → 行内スペースを挿入 (空白追加)   │
│  child.x1 < xt.x0        → 行折り返し検出 (改行追加)        │
│  cls != xt_cls           → 新しい段落を作成                 │
└─────────────────────────────────────────────────────────────┘
```

**コード例** (行400-408):
```python
if cls == xt_cls:               # 同じ段落
    if child.x0 > xt.x1 + 1:    # 行内スペースを挿入
        sstk[-1] += " "
    elif child.x1 < xt.x0:      # 折り返しが生じた場合
        sstk[-1] += "\n"        # 改行を挿入
        pstk[-1].brk = True     # 改行フラグを設定
else:                           # 新しい段落を作成
    sstk.append("")
    pstk.append(Paragraph(...))
```

### A.4 数式の検出

数式は別途グループ化され、`{v0}`, `{v1}`のようなプレースホルダーで表現:

```python
# 数式判定条件
if (
    cls == 0                           # レイアウトクラスが除外領域
    or child.size < pstk[-1].size * 0.79  # 上付き/下付き文字
    or vflag(child.fontname, char)     # 数式フォント
):
    cur_v = True  # 数式として扱う
```

**数式フォント判定** (vflag関数):
- LaTeX系フォント: `CM*`, `MT*`, `TeX-*`, `*Math`, `*Sym`
- 記号カテゴリ: 修飾記号、数式記号、ギリシャ文字

### A.5 Phase A の出力

| 変数 | 内容 |
|------|------|
| `sstk` | 段落テキストのリスト |
| `pstk` | 段落属性(Paragraph)のリスト |
| `var` | 数式文字グループのリスト |
| `vlen` | 各数式の幅 |

**例**:
```
sstk[0] = "Hello World {v0} is a formula"
pstk[0] = Paragraph(y=700, x=50, x0=50, x1=300, size=12, brk=True)
var[0] = [LTChar('∫'), LTChar('x'), LTChar('dx')]
vlen[0] = 45.6
```

## Phase C: 出力PDFの再レイアウト

**ファイル**: `converter.py` 行483-827
**目的**: 翻訳テキストを元の段落境界内にレンダリング

### C.1 フォントサイズのスケーリング

翻訳後のテキストが元の領域に収まるよう、フォントサイズを調整します。
**3つの戦略**が段落の特性に応じて適用されます。

#### 戦略の概要図

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    フォントスケーリング戦略                              │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│  【戦略1】幅ベース (brk=False: 改行なし段落)                            │
│  ────────────────────────────────────────                               │
│  目的: テキスト全体が1行に収まるようにする                              │
│                                                                          │
│    元の境界幅: 250px                                                     │
│    翻訳テキスト幅: 350px (12ptで計算)                                   │
│    → scale = 250 / 350 = 0.71                                           │
│    → フォントサイズ: 12pt × 0.71 = 8.5pt                                │
│                                                                          │
│  【戦略2】トークンベース (brk=True: 改行あり段落)                        │
│  ────────────────────────────────────────                               │
│  目的: 最長の「分割不可シーケンス」が1行に収まるようにする              │
│                                                                          │
│    "分割不可シーケンス"とは:                                            │
│    - メールアドレス: joonspk@stanford.edu                               │
│    - URL: https://example.com                                           │
│    - ASCII単語: Stanford                                                │
│    ※ CJK文字は各文字で分割可能                                         │
│                                                                          │
│    例: "スタンフォード大学 joonspk@stanford.edu"                        │
│    最長トークン: "joonspk@stanford.edu" (120px)                         │
│    境界幅: 92px                                                          │
│    → scale = 92 / 120 = 0.77                                            │
│                                                                          │
│  【戦略3】高さベース (brk=True: 改行あり段落)                            │
│  ────────────────────────────────────────                               │
│  目的: 総テキスト行数が段落の高さに収まるようにする                     │
│                                                                          │
│    推定行数: 総テキスト幅 / 利用可能幅 = 500px / 100px = 5行            │
│    最大行数: 段落高さ / (フォントサイズ × 行送り) = 30px / 13.2 = 2.3行 │
│    → scale = 2.3 / 5 = 0.46 → 0.5 (最小値適用)                          │
│                                                                          │
│  【共通】最小スケール: 0.5 (50%以下にはしない = 可読性維持)             │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 戦略の適用フロー

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      スケーリング判定フロー                              │
│                                                                          │
│  翻訳テキスト + 段落属性                                                │
│         │                                                                │
│         ▼                                                                │
│  ┌─────────────────┐                                                    │
│  │ brk = False?    │──Yes──▶ 【戦略1】幅ベーススケーリング             │
│  └────────┬────────┘                                                    │
│           │No                                                            │
│           ▼                                                              │
│  ┌─────────────────────────────┐                                        │
│  │ 最長トークン > 利用可能幅?  │──Yes──▶ 【戦略2】トークンベース       │
│  └────────────┬────────────────┘                                        │
│               │No                                                        │
│               ▼                                                          │
│  ┌─────────────────────────────┐                                        │
│  │ 推定行数 > 最大行数?        │──Yes──▶ 【戦略3】高さベース           │
│  └────────────┬────────────────┘                                        │
│               │No                                                        │
│               ▼                                                          │
│         スケーリング不要                                                 │
│         (元のフォントサイズを使用)                                       │
└─────────────────────────────────────────────────────────────────────────┘
```

**コード例** (行606-632):
```python
if not brk:
    # 改行なし: 全テキストを1行に
    estimated_width = _estimate_text_width(new, size)
    if estimated_width > available_width:
        scale_factor = available_width / estimated_width
        size = size * max(scale_factor, 0.5)
else:
    # 改行あり: 最長トークンベース
    max_token_width = _get_max_token_width(new, size)
    if max_token_width > available_width:
        scale_factor = available_width / max_token_width
        size = size * max(scale_factor, 0.5)
```

### C.2 トークン幅の計算

「トークン」とは改行不可能な文字シーケンス:

```python
def _get_max_token_width(text: str, font_size: float) -> float:
    # トークン境界:
    # - 空白・改行
    # - CJK文字 (ord >= 0x3000) の後

    # 非トークン境界:
    # - ASCII文字の連続 (メールアドレス、URL等)
```

**例**:
```
"Hello World joonspk@stanford.edu"
  ↓
トークン: ["Hello", "World", "joonspk@stanford.edu"]
最長トークン幅: joonspk@stanford.edu の幅
```

### C.3 文字のレンダリング

各文字を順次処理し、PDF描画命令を生成:

```
┌────────────────────────────────────────────────────────────────┐
│                    文字レンダリングループ                       │
├────────────────────────────────────────────────────────────────┤
│                                                                 │
│  while ptr < len(new):                                          │
│      │                                                          │
│      ├─▶ 数式マーカー {v0} を検出                               │
│      │   └─▶ 元の数式文字を絶対座標で描画                       │
│      │                                                          │
│      ├─▶ 改行文字 \n を検出                                     │
│      │   └─▶ バッファをフラッシュし、次の行へ移動               │
│      │                                                          │
│      ├─▶ 通常文字を処理                                         │
│      │   ├─▶ フォント選択 (tiro/noto)                           │
│      │   ├─▶ 文字幅を計算                                       │
│      │   └─▶ バッファに追加                                     │
│      │                                                          │
│      └─▶ 行末到達時の改行判定                                   │
│          └─▶ _is_breakable_char() で改行可否を判定              │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### C.4 改行可能文字の判定

```python
def _is_breakable_char(ch: str) -> bool:
    # 改行可能:
    # - 空白、改行、タブ
    # - CJK文字 (ord >= 0x3000)

    # 改行不可:
    # - ASCII文字 (単語の途中で切れない)
```

### C.5 PDF描画命令の生成

```python
def gen_op_txt(font, size, x, y, rtxt):
    return f"/{font} {size:f} Tf 1 0 0 1 {x:f} {y:f} Tm [<{rtxt}>] TJ "
```

**PDF描画命令の構造**:
```
BT                    # Begin Text
/noto 12.0 Tf         # フォント設定
1 0 0 1 50 700 Tm     # 位置設定 (x=50, y=700)
[<0048006500...>] TJ  # 16進エンコードされたテキスト
ET                    # End Text
```

### C.6 行送りの調整

段落の高さに収まるよう、行間を動的に調整:

```python
line_height = default_line_height  # 言語による初期値

# 高さに収まるまで行間を縮める
while (lidx + 1) * size * line_height > height and line_height >= 1:
    line_height -= 0.05
```

**言語別デフォルト行送り**:
| 言語 | 行送り係数 |
|------|-----------|
| 中国語 | 1.4 |
| 日本語 | 1.1 |
| 韓国語 | 1.2 |
| 英語 | 1.2 |
| ロシア語 | 0.8 |

### Paragraph クラス

```python
class Paragraph:
    y: float      # 初期の縦座標 (描画開始Y)
    x: float      # 初期の横座標 (描画開始X)
    x0: float     # 左境界

    vertical_spacing: float
```

### フォント選択ロジック

```python
fcur_ = None
try:
    if self.fontmap["tiro"].to_unichr(ord(ch)) == ch:
        fcur_ = "tiro"  # ラテン文字
except Exception:
    pass
if fcur_ is None:
    fcur_ = self.noto_name  # 非ラテン文字
```

### Notoフォントの問題

Notoフォントは元PDFフォントより約15%幅広いため、フォントスケーリングが必要です。

## レイアウト検出

### DocLayout-YOLOモデル

```python
# high_level.py での使用
pix = doc_zh[page.pageno].get_pixmap()
image = np.frombuffer(pix.samples, np.uint8).reshape(pix.height, pix.width, 3)
page_layout = model.predict(image, imgsz=int(pix.height / 32) * 32)[0]
```

### 検出クラス

| クラス | 処理 |
|-------|------|
| `abandon` | 除外 |
| `figure` | 除外（図） |
| `table` | 除外（表） |
| `isolate_formula` | 除外（独立数式） |
| `formula_caption` | 除外（数式キャプション） |
| その他 | テキスト領域として処理 |

### レイアウトマップ

```python
box = np.ones((pix.height, pix.width))  # 初期値1
# テキスト領域を番号付け
box[y0:y1, x0:x1] = i + 2  # 領域ごとに異なる番号
# 除外領域を0に
box[y0:y1, x0:x1] = 0
```
